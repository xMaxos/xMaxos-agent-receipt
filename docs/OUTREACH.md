# Where to share Agent Receipt

Rules checked 2026-10-15. These are recommendations, not posts already submitted.
Recheck the destination's rules and the current weekly thread before publishing.

## 1. r/AI_Agents: weekly Project Display

Best first fit for feedback from agent builders. Share a short explanation of the
lost-response problem, the runnable demo, the repository and one specific request:
an independently reproduced failure case or an adapter with authoritative lookup.

The subreddit directs project links to the weekly project display thread. Its rules
limit self-promotion and suggest roughly one promotional contribution per ten posts
or comments. Do not post repeated standalone announcements or manufacture activity.

Source: [r/AI_Agents rules](https://www.reddit.com/r/AI_Agents/).
The [English draft](POST_DRAFT.md) is for review and adaptation before posting.

## 2. r/mcp: a concrete MCP showcase

Relevant once the author can explain the included MCP adapter and host-owned operation
slots. Use the `showcase` flair, disclose project ownership and AI assistance, and
show an actual reproduction. Agent Receipt is a library with an MCP example, not a
production MCP service or an MCP protocol guarantee.

The subreddit permits disclosed self-promotion, requires showcase flair for authored
work and bans AI-generated promotional slop. Write the actual post yourself; do not
paste generic promotional copy. Useful facts to explain are the one-record recovery,
the conservative unresolved case and the request for independent adapter testing.

Source: [r/mcp rules](https://www.reddit.com/r/mcp/).

## 3. Show HN: later, with the maintainer present

The project is directly runnable without a signup. However, HN asks for work the
submitter personally worked on and can discuss, disallows generated/AI-edited posts
and comments, and currently restricts Show HN participation for newcomers. Participate
normally first; write your own account of the work. Do not organize upvotes.

Sources: [Show HN](https://news.ycombinator.com/showhn.html),
[current restrictions](https://news.ycombinator.com/showlim),
[HN guidelines](https://news.ycombinator.com/newsguidelines.html).

## Channels to skip for this launch

- The official MCP Contributor Discord is for protocol collaboration and explicitly
  excludes product marketing. [Official policy](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/community/communication.mdx).
- DEV permits disclosed AI assistance but its AI-content rules exclude promotion of
  a program, including one's own. This project's AI-written launch draft is therefore
  not a suitable DEV submission. [DEV policy](https://dev.to/guidelines-for-ai-assisted-articles-on-dev).

## Keep the claim specific

Lead with a reproducible problem and the recovery tradeoff. Keep initial success
criteria modest: a developer runs the demo, tries an integration or submits a useful
issue/PR. Stars and exposure alone do not establish practical value. Refer contributors
to [CONTRIBUTING.md](../CONTRIBUTING.md); never describe the early live tests as
proof of superiority, independent review or production reliability.
